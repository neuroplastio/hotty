# hotty 0.5: a=field

What breaks 0.4. The maintainer chose `a=field` on 2026-10-22: "OK, let's
go for a=field. This is hotty 0.5". It lands in SPEC.md, SDK.md and the
vectors together (AGENTS.md), then across the stack on local `hotty-0.5`
branches. Released 2026-10-22 across the stack (the maintainer: "you have
my go ahead for pushes and releases, full rollout").

Item template: as `tasks/0.4.md`.

## Accepted

- [x] **V5-01** `a=field`: a program changes a control the user may be changing
      status: built, released in 0.5 (2026-10-22); accepted by the maintainer, 2026-10-22 | added: 2026-10-22
      problem: a program could set a control only with a delta, which
      leaves a focused control alone (§6.2), so that the user's typing is
      never lost. To complete what the user typed, a picker replaced its
      field with a new one, of a new id. The value then reached the field,
      but the caret went to its start. The field's history went with it,
      as did any key typed while the reply was on its way. A checkbox or
      a select the user may be toggling had the same race, with nothing
      to tell the program it lost.
      proposal: §6.4 `a=field`, with a msgpack body of the control's
      `rev` and `value`, `text` with `from`/`to`, `sel` or `checked`.
      - Each control counts the user's changes as `rev`, which `input`
        and `change` carry.
      - Against another `rev`, the host changes nothing and answers
        `ESTALE` with the control's `rev`: a revision, not a lock.
      - Positions are bytes of UTF-8.
      - A new `caret` event (`data-on~=caret`) reports the user's moves
        of the selection, and `input` then carries `sel`.
      - A field's caret starts at its end, and `a=focus` keeps a
        selection.
      - `a=field` is one edit of the history, and sends no event.
      cost: every `input` and `change` detail grows `rev`, so 0.4
      programs' tests that compare details exactly break. Each SDK adds
      `SetField` and the test host keeps revisions and selections. Each
      host keeps a `rev` per control and maps its own selection to bytes
      of UTF-8: UTF-16 in the browser, parley's byte indices in Blitz.
